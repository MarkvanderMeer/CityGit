# CityGit
MSc Thesis: CityGit

The files are summarized:
CLI and helper modules
- `cjv.py` — Main command-line entry point for the tool; wires Click commands like log, checkout, diff, commit, branch, merge, and rehash.
- `cjv_commands.py` — Implements the command behavior: history logging, checkout extraction, diffs, rehashing, commits, branches, and merges.
- `helper-functions/graph.py` — Builds and prints the version DAG/history graph in simple or tree-like formats.
- `helper-functions/utils.py` — Shared utility functions for CityJSON loading/saving, hashing, versioned-object comparison, geometry index updates, and generic version-ref resolution helpers.

CityJSON package
- `cityjson/init.py` — Empty package initializer for the cityjson module.
- `cityjson/citymodel.py` — Core CityJSON model classes: CityJSON, CityObject, object dictionaries, vertex indexing, and coordinate transform logic.
- `cityjson/versioning.py` — Versioning system for CityJSON: refs, versions, branches, tags, ancestry, hashes, and diffing between versions.

Tests and validation
- `tests/test_versioning.py` — Unit tests covering empty versioned models, hash calculations, version creation, object diffing, and sample dummy-data changes.
- `tests/test_citymodel.py` — Tests for CityJSON loading, transforms, and indexed vertex dereferencing/reference behavior.
- `tests/test_commands.py` — Tests for the commit command and version creation flow.
- `tests/test_hausdorff.py` — Experimental script for computing a Hausdorff-like distance between CityJSON vertex sets using SciPy cKDTree.

Project docs and packaging
- `project-docs/LICENSE.md` — MIT license for the project.
- `project-docs/README.md` — Main project documentation: setup, usage, commands, and examples for versioned CityJSON workflows.
- `project-docs/old_README.md` — Duplicate copy of the README; appears to be an unneeded backup or earlier draft.
- `helper-functions/setup.py` — Package metadata and dependency list for the CLI tool; registers the cjv console entry point.
- `project-docs/pylintrc` — Lint configuration for Pylint style and warnings.
- `init.py` — Empty package marker file at the repo root.
- `cjv.egg-info/PKG-INFO` — Generated metadata describing the package version and summary.
- `cjv.egg-info/SOURCES.txt` — Generated list of packaged source files.
- `cjv.egg-info/dependency_links.txt` — Generated dependency-link metadata.
- `cjv.egg-info/entry_points.txt` — Declares the cjv command-line entry point.
- `cjv.egg-info/requires.txt` — Runtime dependency list generated by packaging.
- `cjv.egg-info/top_level.txt` — Lists top-level Python modules.

Example CityJSON datasets
- `datasets/unit-cubes/2-unit-cube-extension.json` — Cube model with added extension data; used to test non-trivial geometry variations.
- `datasets/unit-cubes/2-unit-cube-moved.json` — Same cube moved in space; used to test transformation/diff logic.
- `datasets/unit-cubes/2-unit-cube-wrong.json` — Incorrect or invalid cube variant used for error-case testing.
- `datasets/unit-cubes/torus.json` — Torus-shaped sample model to exercise geometry handling.
- `datasets/unit-cubes/unit-cube-plane.json` — Cube with planar geometry to test surface/mesh assumptions.
- `datasets/unit-cubes/unit-cube-roof.json` — Cube with roof-related geometry variant.
- `datasets/unit-cubes/unit-cube.json` — Baseline unit cube sample model.
- `datasets/unit-cubes/unit-cube_crasher.json` — Crash/edge-case cube variant used for robustness testing.
